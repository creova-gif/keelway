Learn how to build, orchestrate, and verify software using local-first autonomous developer agents, deterministic state machines, and cryptographic proof packets.

1. Quickstart and the three surfaces

Clone https://github.com/creova-gif/kora.git. The directory name is kora. These steps use the repository. They do not use a PyPI package named keelway, and they do not use a keelway.dev installer. Studio, the governance server, and this static page are different processes.

bash
# Clone. The folder is kora.
$ git clone https://github.com/creova-gif/kora.git
$ cd kora
$ python3 -m venv .venv && source .venv/bin/activate
$ pip install -e ".[dev]"

# Local Studio. Browser on 127.0.0.1:7420.
$ python3 cli.py dev
# Browser-app window when Chrome or Chromium is present.
$ python3 cli.py desktop

# Governance server. Separate process on 127.0.0.1:8000.
$ make serve
# After the editable install, the same CLI is:
$ keelway-core serve

# List guided-builder templates. No model call.
$ python3 cli.py build templates

The governance command is make serve, which runs python3 -m keelway.cli.main serve --host 127.0.0.1 --port 8000. After the editable install that module is the keelway-core script. python3 cli.py serve is rejected. Both parsers set prog="keelway", so the governance help text prints usage: keelway. That label is help text. cli.py also has its own run subcommand, separate from keelway-core run. This HTML file is the static site under website/. Opening it does not start Studio.

4. TaskState names and two different HTTP routes

TaskState in core/orchestration/state.py has 16 members: CREATED, CONTEXT_LOADING, PLANNING, PLANNED, PLAN_READY, AWAITING_APPROVAL, RUNNING, EXECUTING, VERIFYING, PAUSED, BLOCKED, AWAITING_RETRY, TIMED_OUT, COMPLETED, FAILED, and CANCELLED. CONTEXT_READY is not a member. The file also holds a transition map. This page does not walk that map, and the Studio agent loop described below does not reference TaskState.

A search of the Python tree does not find a route POST /v1/tasks/{task_id}/cancel. Two routes that do exist are different from each other:

  • POST /v1/tasks/{task_id}/transition in core/api/routes.py requires Permission.EXECUTE_AGENT. The body field is target_state. The handler calls validate_transition. If the stored state is AWAITING_APPROVAL and the target is RUNNING, it also requires Permission.APPROVE_TIER3. It then writes the new state on the task row. The handler that was read does not restore file bytes.
  • POST /v1/agent/cancel/{task_id} requires Permission.EXECUTE_AGENT. If the id is absent from the process dict of active loops, the handler returns 404. AutonomousAgentLoop.cancel terminates active_proc when that process is still running, clears a pending approval, sets the loop status to cancelled, and marks the running step failed. That function does not restore file bytes.

This page does not describe a keyboard interrupt, and it does not describe a rollback of edits already written.

8. KStack Composable Role Skills

KStack standardizes agent roles as version-controlled SKILL.md definitions. Keelway ships with four first-party built-in skills:

  • kstack/plan (Role: Architect) — Deconstructs intent into discrete, bounded, testable steps.
  • kstack/review (Role: Reviewer) — Pre-landing code inspection for subtle edge cases and regressions.
  • kstack/qa (Role: QA Lead) — Surfaces test plans, boundary conditions, and test execution.
  • kstack/security (Role: Security Lead) — Checks threat models, input validation, and credential leaks.

The skill subparsers on cli.py are list, inspect, validate, import, export, and revoke. There is no pin subparser. From a clone: python3 cli.py skill --help. The four SKILL.md files under core/kstack/skills/ are plan, review, qa, and security. The role sentences above were not executed as a run.

9. KBrain Scope-Aware Knowledge & DLP Memory

KBrain provides hierarchical fact and decision memory with strict scoping boundaries: LOCAL_SESSION < PROJECT < TEAM < ORG. Before storing any fact, an automated regex DLP pre-flight scanner validates the payload, immediately throwing SecretLeakDetectedError if raw API keys (sk-, ghp_, Bearer , private keys) are present.

10. KHub Universal Skills Importer

KHub scans and imports agent skills from external platforms, including .claude/skills, .cursor/skills, .cursor/rules, .agents/skills, and .codex/skills. Files under .cursor/rules are strictly classified as non-executable prompt rules (is_rule_only=True) to prevent accidental execution as tool skills. Upstream content changes are actively monitored via SHA-256 drift radar.

11. KSpaces Collaborative Workspaces & RBAC

KSpaces introduces enterprise team collaboration with four RBAC roles: OWNER, AGENT_MANAGER, CONTRIBUTOR, and VIEWER. Agents receive time-bound service account credentials (sa_<id>) with automatic TTL expiration. All proposed branch changes require explicit AGENT_MANAGER review and approval.

12. KFlow Deterministic DAG Engine

KFlow coordinates parallel multi-agent task execution using a topological DAG scheduler with strict maximum dollar budget and fanout constraints. Prior to applying changes, KFlow checks that the working tree matches the approved base Git commit SHA, raising BaseShaDriftError if concurrent edits occurred. Execution produces a cryptographically sealed ProofPacket.

13. Tier 2 Hardware Security HAL Experimental (Simulation)

For high-security defense, banking, and critical infrastructure deployments, Keelway implements a software-simulated model specification for Tier 2 Hardware Abstraction (pending physical hardware qualification):
