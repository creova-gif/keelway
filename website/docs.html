How Keelway works, in plain terms.

Quickstart

Clone the repo and run it locally — no package registry, nothing hosted.

bash
$ git clone https://github.com/creova-gif/kora.git
$ cd kora
$ python3 -m venv .venv && source .venv/bin/activate
$ pip install -e ".[dev]"

# Studio, the local IDE (127.0.0.1:7420)
$ python3 cli.py dev

# Governance server, for teams (127.0.0.1:8000)
$ make serve

The three surfaces

Studio is the local IDE you work in day to day — python3 cli.py dev. The governance server is a separate process for teams that enforces approvals and keeps the shared audit record — make serve. This website is static docs and install instructions; reading it doesn't start or touch anything on your machine.

The approval loop

An agent plans a change, proposes it as a real diff, and stops at anything that mutates your repo. You approve once, approve a scoped standing rule for that tool and path, or deny. Every decision — approved or denied — is written to a local, hash-chained record you can verify independently, with no account or cloud service required.

What's still in progress

Keelway is early. Team workspaces, hosted sync, and customer-owned VPC runners are in active development — see Early Access if you want to be looped in as those ship.
