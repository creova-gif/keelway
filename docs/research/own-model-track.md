# Kora Own-Model Research Track

**Status:** Parallel research track (starts during foundation phase)  
**Goal:** Produce a small, domain-adapted Kora model that outperforms general models on measured Kora tasks, while the main AI Core and Personal Agent continue.  
**Constraint:** Do not block the 90-day infrastructure milestones. Own-model work is research until evaluation evidence justifies promotion.

## Why now (in parallel)

- You want original IP and differentiation.
- The gateway, evaluation harness, and data pipelines being built for the Personal Agent are exactly what a custom model needs.
- Starting data collection and small experiments early avoids a cold start later.
- African-language, engineering-domain, or edge-constrained models are realistic targets; a general frontier LLM is not.

## Phased approach

### Phase A — Data & Evaluation Foundation (Days 1–45, parallel)
**Owner:** Research  
**Do not block Core work.**

1. Define 3–5 Kora-specific task families (from the Personal Agent workflows):
   - Engineering brief generation
   - Code / PR review with citations
   - Research / ADR summarization
   - Test-failure analysis
   - (Optional) African-language technical Q&A
2. Create a seed dataset:
   - Synthetic examples generated by Claude / strong models (with human review)
   - Real anonymized Kora engineering traces (with permission)
   - Public high-quality coding / reasoning data filtered for relevance
3. Store all data with provenance, license, and consent flags in `research/datasets/`.
4. Extend the evaluation suite so every new model (including fine-tunes) is scored on the same tasks as Claude and open-weight baselines.
5. Document data governance (retention, deletion, no private user data in training sets).

**Deliverable:** Versioned seed dataset + evaluation harness that can score any model.

### Phase B — Small-scale adaptation (Days 30–90, parallel)
**Owner:** Research + one engineer (part-time)

1. Choose a strong open base model (e.g. Qwen2.5-7B, Llama-3.1-8B, or a smaller 1–3B for edge).
2. Run supervised fine-tuning (SFT) or LoRA/QLoRA on the seed dataset.
3. Compare against:
   - Base open model
   - Claude (or strongest hosted model)
   - Prompt-engineered base model
4. Measure: task accuracy, citation quality, latency, memory footprint, cost.
5. Only continue if the fine-tune shows a clear, repeatable gain on at least two Kora task families.

**Deliverable:** First Kora-adapted checkpoint + comparison report.

### Phase C — Domain model decision gate (Day 90+)
**Owner:** Lead + Research

- If evaluation evidence is strong → invest in larger dataset, continued pre-training or larger fine-tune, and serving integration via the gateway.
- If evidence is weak → keep using the multi-provider gateway and treat own-model work as ongoing research.
- Explicitly defer any general frontier-scale training until infrastructure, data quality, and evaluation maturity justify it.

## Technical starting stack (research only)

| Component              | Choice                          | Notes                                      |
|------------------------|---------------------------------|--------------------------------------------|
| Base model             | Qwen2.5-7B or Llama-3.1-8B     | Strong coding / reasoning, open weights    |
| Fine-tuning            | LoRA / QLoRA (Unsloth or Axolotl) | Low VRAM, fast iteration                   |
| Data format            | ShareGPT / OpenAI messages      | Easy conversion from gateway logs          |
| Evaluation             | Existing Kora eval suite        | Must beat or match Claude on target tasks  |
| Serving                | vLLM or Ollama via LocalAdapter | Already supported by the gateway           |
| Experiment tracking    | Simple JSON + git or Weights & Biases | Keep lightweight at first                |

## Data sources (priority order)

1. Synthetic data generated by Claude on Kora workflows (human-reviewed).
2. Anonymized internal engineering traces (PR reviews, briefs, test analyses) with explicit consent.
3. Curated public datasets (coding, reasoning, technical documentation).
4. African-language technical content (if that becomes a priority) — collected and cleaned carefully.

## Risks and mitigations

- **Data quality / leakage** → Provenance tracking, no private data in training, human review of synthetic data.
- **Distraction from Core** → Cap research time; own-model work cannot delay the three Personal Agent workflows.
- **No measurable gain** → Treat as research; do not force a model into production.
- **Compute cost** → Start with LoRA on a single GPU or cloud spot instance; avoid full pre-training early.

## Integration with AI Core

- Any successful checkpoint is served through the existing `LocalAdapter` or a new `KoraModelAdapter`.
- The routing policy can prefer the Kora model for tasks where it has proven superior, and fall back to Claude otherwise.
- Evaluation results are stored alongside other provider results so the gateway policy can be data-driven.
