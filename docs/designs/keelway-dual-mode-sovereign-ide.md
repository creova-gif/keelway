## Problem Statement
Software engineering teams attempting to scale AI-assisted development across multiple concurrent coding agents face severe coordination breakdown: isolated git worktrees collide on runtime environments (localhost ports, `.env` configs, shared test databases), lack of deterministic rollback when agents fail, and compliance violations when sending proprietary intellectual property to cloud-hosted LLMs.

## Demand Evidence
Pre-product beta stage. Verified technical feasibility with 745 automated tests, client SDK, and an active desktop Studio UI, but zero verified external demand or daily dependencies outside the founding team. The unvalidated demand hypothesis is that engineering leads running multiple coding agents will voluntarily adopt a dedicated coordination and flight recording layer to eliminate worktree chaos and audit multi-agent code mutations.

## Status Quo
Developers run multiple terminal agents or CLI tabs (Claude Code, Cursor, custom scripts) in parallel, manually managing separate git worktrees, manually symlinking `.env` files, resolving localhost port collisions, manually cherry-picking clean commits, and tediously diagnosing regressions without deterministic flight tapes or policy governance.

## Target User & Narrowest Wedge
- **Target User**: Engineering Lead / Platform Lead operating concurrent AI coding agents on production repos (e.g., Rigel St. Pierre at Rootly).
  - *Gets them promoted*: Safely increasing team engineering velocity by 3-5x without multiplying bug triage, review fatigue, or worktree collision overhead.
  - *Gets them fired*: An unmonitored agent hallucinating a broken database migration, overwriting a coworker's branch, or leaking private API credentials into cloud LLM logs.
- **Narrowest Wedge**: A dual-mode sovereign developer platform: an installable standalone Desktop IDE with built-in agent orchestration and deterministic flight recording, coupled with a 1-click live-sync bridge that allows developers to seamlessly inspect or edit the same active worktrees in their favorite external editor (VS Code / Cursor).

## Constraints
- **Air-Gap Zero-Egress Compliance**: Must strictly enforce local operation (NIST SP 800-53 SC-7); the UI canvas must never load third-party CDNs, fonts, or tracking scripts.
- **Zero-Mock Policy**: Every dashboard metric, status pill, and control must reflect real underlying system state and verified passing tests.
- **Local-First & Multi-Provider**: Support local hardware acceleration (Apple Silicon MLX, local Ollama/vLLM) with pluggable access to authorized cloud models.
- **Brand Separation**: Maintain strict operational separation between Keelway by Sorvex Labs (infrastructure platform) and Kora Technologies.

## Premises
1. **Standalone Sovereign IDE**: Keelway must be an installable, sovereign desktop IDE (code editor, terminal, Git tree, agent task board) where agent orchestration and flight recording are first-class primitives deeply woven into the editor canvas.
2. **Sovereign Differentiation**: Its winning edge over cloud-tethered IDEs (Cursor, Windsurf) is sovereignty, zero-egress compliance, deterministic flight tapes, and collision-free worktree management.
3. **Frictionless Distribution**: Teams can install Keelway in one command (`install.sh`), launch it locally, and start delegating tasks without mandatory account creation or cloud vendor lock-in.

## Approaches Considered
- **Approach A: Minimal Viable — Sovereign Desktop Shell + Local Core Server**
  - Summary: Package Keelway Studio (Monaco + FastAPI core) as a single standalone executable bundle.
  - Rejected because: While fast to ship, a pure web-app shell without external editor sync introduces friction for developers who want to keep their existing extensions while evaluating agents.
- **Approach B: Custom VSCodium / Code-OSS Fork**
  - Summary: Fork Microsoft Code-OSS to build a native Electron binary with Keelway agent/flight recorder engine baked in.
  - Rejected because: Maintaining an upstream VS Code fork requires massive continuous engineering overhead and months of delay before putting the product in front of real users.

## Recommended Approach
**Approach C: Dual-Mode Sovereign IDE (Finish Standalone Keelway Desktop IDE + Live Sync Bridge)**
- Complete the standalone Keelway Desktop IDE with native Monaco editor, terminal, Git staging, and 6 primary beta areas (Tasks, Files, Record, Labs, Settings, Evidence).
- Add a 1-click "Open Worktree in VS Code / Cursor" live-sync bridge so engineers who want to stay in their current editor can do so while Keelway autonomously runs parallel agents, isolates environments, and records flight tapes in the background.
- Ships immediately on top of the existing 745 passing tests and production `install.sh` pipeline.

## Success Criteria
1. At least 2 of the 5 prospective engineering leads (starting with Rootly workflow) commit to running a 2-week pilot on an internal repo.
2. Pilots demonstrate repeat voluntary usage (>3 delegated multi-agent tasks per week per user).
3. Zero unhandled worktree or port collisions during parallel agent execution.
4. Clean 1-command installation (`curl -fsSL https://kora-sable.vercel.app/install.sh | bash`) succeeding across macOS and Linux machines.

## Distribution Plan
- Distribution Artifact: Universal standalone installer script served from `https://kora-sable.vercel.app/install.sh`.
- Packaging: Local Python virtualenv + compiled `keelway_core` Rust/C extensions + pre-bundled zero-CDN static Studio assets.
- CI/CD Pipeline: GitHub Actions + Vercel deployment with automated 20-stage developer journey gate (`test_full_beta_developer_journey.py`).

## Dependencies
- Local Python 3.10+ runtime or bundled standalone runtime.
- Git 2.38+ with worktree support.
- Local model runtime (Ollama, MLX, or llama.cpp) or authorized cloud API keys.
